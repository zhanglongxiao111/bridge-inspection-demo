# 全局体验与底层架构提升计划 (UX & Engine Enhancement Plan)

## 0. 导言
当前系统虽然在前端视觉和 UI 状态流转上初步具备了 SaaS 级平台的雏形，但在**底层仿真引擎**、**大/小场景空间联动**以及**交互沉浸感**方面仍处于非常“简陋”的原型阶段。
本计划旨在深入复盘现有代码库，提出面向“工业级高精度数字孪生”演进的全面升级方案。

---

## 1. 📁 项目目录与架构整理 (Project Directory Restructuring)
**现状痛点**：目前项目目录“乱七八糟”，所有的逻辑（包含 UI、3D 渲染、初始化）高度耦合在根目录下的 main.js 和 index.html 中，静态资源 (图片) 也散落在 public/ 目录下缺乏分类。
**提升方案**：
- **资源分类 (Assets Management)**：在 public/ 下建立 /textures, /models, /ui, /icons 等子目录，将散落的图片、图标和即将引入的高精模型进行归类存放。
- **源码拆分 (Source Code Modularization)**：
  - 建立 /src 目录，将入口代码从根目录移入。
  - 将 main.js 拆解为：src/core/Renderer.js (Three.js 核心逻辑), src/core/DroneController.js (飞行物理), src/ui/UIManager.js (DOM 操作与面板控制), src/ui/Kanban.js (工作流看板)。
- **组件化 (Componentization)**：利用 Vite 的特性，逐步将冗长的 HTML 拆分为独立的小模板文件（甚至考虑引入轻量级组件库或 Web Components）。

---

## 2. 🌍 宏观与微观空间联动重构 (Macro-Micro Transition)
**现状痛点**：目前“指挥中心（Cesium 地球）”和“飞行控制（Three.js 局部场景）”是两个完全割裂的独立 DOM 容器，切换时只是生硬的 CSS 隐藏与显示，毫无空间连续性。
**提升方案**：
- **地理坐标映射 (Geo-Referencing)**：建立 Cesium 经纬度 (WGS84) 与 Three.js 局部直角坐标系的矩阵转换关系。
- **无缝拉近动画 (Seamless Zoom-in)**：在指挥中心点击具体大桥节点时，触发 Cesium 相机的极致拉近动画；当视角高度降低到阈值（如 500m）时，利用 WebGL 遮罩或 Alpha 过渡，平滑溶解进入 Three.js 的高精度桥梁渲染场景。
- **反向联动**：在局部 FPV 飞行时，右上角的二维缩略图应与 Cesium 的视角保持小地图级别的同步更新。

---

## 3. 🛸 无人机仿真引擎重置 (Drone Physics & Assets)
**现状痛点**：目前无人机仅由几个 `THREE.BoxGeometry` 拼接而成，物理飞行仅靠简单的 `translateZ` 线性位移计算，毫无惯性、空气动力学和真实感。
**提升方案**：
- **高精模型替换**：引入经过减面和 Draco 压缩的真实无人机 `.glb` 静态模型（如 DJI M350 RTK），包含折叠桨叶的细节。
- **真实物理引擎 (Cannon.js / Ammo.js)**：抛弃当前的线性增量，引入刚体动力学。加入质量、阻力系数、推重比公式。按 WASD 时计算的是受力 (Force) 而非位移。
- **动态天气耦合**：
  - **风阻计算**：将系统面板上的“风速 (2.4 m/s)”与无人机的位移进行向量叠加。大风侧吹时，无人机必须自动倾斜机身 (Pitch/Roll) 进行姿态补偿。
  - **高度气压模拟**：随着飞行高度的增加，模拟更猛烈的气流抖动 (Camera Shake)。

---

## 4. 🛡️ 环境感知与交互反馈 (Environment & Collision)
**现状痛点**：当前无人机可以穿模飞跃桥墩，遇到海平面不会坠机，完全是一台“幽灵摄像机”。
**提升方案**：
- **射线检测 (Raycasting) 避障导航**：
  - 在无人机前方、上方、下方发射 3D 射线 (Octree 碰撞检测优化)。
  - 当检测到距离桥柱小于 2m 时，自动触发 `Obstacle Avoidance` 逻辑进行平滑绕行，并切断 WASD 往前的强行输入。
- **海平面物理反馈**：当无人机 `Y` 轴坐标接触到水面 (`Y=0` 以下) 时，触发坠毁逻辑。利用 Three.js 粒子系统 (Particle System) 生成溅水动画 (Water Splash) 和报错警报声。

---

## 5. 🚀 彩蛋功能：战术武装拓展 (Tactical Payload)
**现状痛点**：缺乏趣味性。
**提升方案**：
- 在系统管理界面增加“隐藏开发者模式”，激活后无人机底部挂载模块切换为“导弹发射器”。
- **交互**：在 FPV 模式下，右键瞄准锁定，左键发射。
- **视觉效果**：利用线段生成导弹轨迹，击中海面或指定病害点时播放爆炸特效碎片与火光，增强演示项目的话题性和演示震撼感。

---

## 6. 🔀 其他代码层面的重构 (Code Refactoring)
1. **动画曲线平滑化**：当前上帝视角双击切换目标时，使用的线性 `lerp` 导致镜头僵硬。需改用 `TWEEN.js` 或 `GSAP` 实现 Ease-In-Out 平滑曲线。
2. **路径可视化 (Path Line)**：目前使用尖锐的直线连接航点。需采用 `THREE.CatmullRomCurve3` 生成曲线航迹，让自动导航的飞行路线更符合空气动力学轨迹。
3. **性能优化**：水面目前是简单的透明平面，应当引入 `WaterShader` 替换现有的蓝色平面，增加海浪起伏和环境光反射，以匹配暗色主题的宏大感。
4. **架构解耦**：将当前的 `main.js` 拆分为 `Renderer.js`, `UIManager.js`, `InputController.js`，避免随着功能激增导致单文件膨胀。

## 7. 💼 业务级功能页签深度演进 (Business-Level Tab Enhancements)
除了飞行控制与物理引擎外，作为完整的 SaaS 平台，其他三大顶栏页签（资源管理、工作流、系统管理）目前的静态展示距离“生产可用”仍有差距，计划在未来引入以下真实业务逻辑：

### 7.1 资产设备全息档案 (Resource Management)
- **IoT 遥测数据动态化**：目前设备的电量、网络状态是静态文本。计划接入 WebSocket (模拟)，实时反映无人机的电池循环衰减 (Battery Degradation) 和机巢 (DJI Dock) 的内部温湿度曲线。
- **3D 资产拆解试图**：摈弃简单的 <img> 卡片。点击列表中的 M350 无人机或机巢时，直接在右侧弹出一个极轻量级的 WebGL 画布，展示该硬件的 **3D 爆炸图 (Exploded View)**，用于指导运维人员更换特定桨叶或电池组。

### 7.2 自动化巡检工作流 (Workflow Kanban)
- **空间连动溯源 (Spatial Tagging)**：打破纯文本 Kanban 的局限。在看板中点击“#DEF-102 深度裂缝”病害卡片时，系统应当自动切换回【飞行控制】的 3D 页面，控制相机飞到桥墩的具体 (X, Y, Z) 坐标，并在模型表面高亮出该裂缝。
- **动态拖拽与报告生成**：引入拖拽 API (Drag & Drop)。允许审核员将卡片从“人工复核”拖拽到“维修工单”栏。并在流水线末端增加“导出巡检报告 (PDF/Word)”功能，整合该批次的所有病害截图与坐标数据。

### 7.3 系统底层配置 (System Management)
- **AI 模型热切换与端侧推理**：目前 AI 引擎只是下拉框假装切换。计划引入 ONNX.js 或 WebNN，允许浏览器在本地加载轻量级的 YOLO 权重文件，真正对视频流截图进行实时的前端推理检测。
- **RBAC 权限与电子围栏 (Geo-fencing)**：
  - 增加“管理员/操作员”视图区分。
  - 在参数面板中增加 2D 地图圈绘功能，允许用户在桥梁周边划定“禁飞区 (No-Fly Zones)”，一旦后续真实飞行的物理引擎检测到越界，强制触发悬停并告警。
